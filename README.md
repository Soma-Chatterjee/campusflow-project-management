# CampusFlow — End-to-End Project Management Case Study

> **A simulated cross-functional project demonstrating end-to-end project management, stakeholder management, planning, risk management, Agile delivery, change control, communication, and project closure.**

---

## 📌 Project Overview

**CampusFlow** is an end-to-end project management case study based on a proposed **student-success initiative**.

The project addresses a common challenge faced by university students: managing academic responsibilities, deadlines, priorities, and collaborative work across multiple disconnected tools.

The objective of this portfolio project is **not primarily to demonstrate software development**. Instead, it demonstrates how a Project Manager can take an initiative from **business problem identification through planning, execution, monitoring, change management, validation, and closure**.

### Project Role

**Project Manager**

### Project Type

**Cross-functional Product Delivery Initiative**

### Methodology

**Hybrid Project Governance + Agile/Scrum Delivery**

### Planned Duration

**12 Weeks**

### Illustrative Budget

**₹5,00,000**

---

# 🎯 Project Objective

The primary objective is to plan and manage the delivery of a focused MVP for a student-success solution while maintaining control over:

* Scope
* Schedule
* Budget
* Resources
* Risks
* Stakeholders
* Requirements
* Quality
* Communication
* Change requests

The project concludes with **User Acceptance Testing, project closure, lessons learned, and Phase 2 recommendations**.

---

# 🏢 Business Problem

University students often manage academic responsibilities through a combination of:

* Learning Management Systems
* Calendars
* Messaging applications
* Notes
* To-do lists
* Spreadsheets

This fragmented approach can make it difficult to maintain visibility over:

* Assignments
* Deadlines
* Priorities
* Group-project responsibilities
* Overall workload

### Proposed Opportunity

CampusFlow proposes a centralized student-success experience that helps students:

> **Plan → Prioritize → Track → Collaborate → Complete**

# 🔄 Change Management

One of the key project-management scenarios involves a mid-project change request.

## Change Request CR-001

### Requested Change

Add an **AI-powered study planner** to the MVP.

### Impact Assessment

| Dimension           | Impact                         |
| ------------------- | ------------------------------ |
| Business Value      | High                           |
| Scope               | High                           |
| Schedule            | +3 weeks                       |
| Illustrative Budget | +₹75,000                       |
| Resources           | Additional specialist required |
| Risk                | High                           |

### Project Manager Recommendation

> **Defer the feature to Phase 2.**

### Rationale

Although the proposed feature could provide significant future value, introducing it during MVP delivery would create substantial scope, schedule, resource, and delivery risk.

Protecting the committed MVP timeline was considered the better project-management decision.
